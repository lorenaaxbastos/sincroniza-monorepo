# Document shell (`Page.astro` / `sincronizaHtmlPlugin`)

O **document shell** é a casca HTML raiz da aplicação. Ele é responsável por renderizar a estrutura inicial do documento (`<html>`, `<head>`, `<body>`), gerenciar meta tags de SEO/OpenGraph, aplicar o script anti-flash de tema, injetar recursos globais de acessibilidade (Skip Link e HandTalk), o overlay global de modais e rastreamento (Google Analytics).

<div style={{marginBottom: '6rem'}}></div>

## Onde utilizar cada solução?

* **Astro (`apps/clients`, etc.):** Importe e utilize o componente `Page.astro` como a camada mais externa de todas as suas páginas.
* **Vite / React / SPA (`apps/docs`, `apps/clients`, etc.):** Adicione o plugin `sincronizaHtmlPlugin` no arquivo `vite.config.ts` do seu projeto. Ele injetará automaticamente a mesma estrutura HTML, os scripts de tema, o overlay global e os skip-links no seu `index.html`.

<div style={{marginBottom: '4rem'}}></div>

## 3. Plugin `sincronizaHtmlPlugin` (para projetos Vite / React)

Em aplicações React ou SPAs construídas com Vite, não existe o contexto do Astro para renderizar `<html / head / body>`. Para garantir que a aplicação React receba exatamente os mesmos recursos globais, utilizamos o plugin do Vite do nosso pacote `@sincroniza/ui`. As props aceitas são as mesmas do `Page.astro`, mencionada anteriormente na [Tabela de props](#tabela-props).

<div style={{marginBottom: '2rem'}}></div>

### Configuração no `vite.config.ts`

```typescript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { sincronizaHtmlPlugin } from '@sincroniza/ui/plugins';

export default defineConfig({
  plugins: [
    react(),
    sincronizaHtmlPlugin({
      title: 'Painel de Gestão à Vista - Sincroniza Educação',
      description: 'Área logada do Painel de Gestão à Vista',
      googleAnalyticsId: 'G-XYZ123456',
      handTalkToken: 'SEU_TOKEN_HANDTALK',
    }),
  ],
});
```

<div style={{marginBottom: '4rem'}}></div>

### Importação do `global.css` no React

Diferente do `Page.astro` (que importa o CSS automaticamente em projetos Astro), o `sincronizaHtmlPlugin` injeta o HTML e os scripts de tema, mas **não insere o CSS diretamente na página** para respeitar o pipeline do bundler do Vite e o HMR (Hot Module Replacement).

Em projetos React, é **obrigatório** importar o CSS global manualmente no ponto de entrada da aplicação (`src/main.tsx` ou `src/App.tsx`):

```tsx
// src/main.tsx ou src/App.tsx
import '@sincroniza/ui/styles/global.css';
```

## 4. Recursos e comportamentos globais injetados

Tanto o `Page.astro` quanto o `sincronizaHtmlPlugin` injetam automaticamente os seguintes scripts e elementos na casca da aplicação:

<div style={{marginBottom: '2rem'}}></div>

### A. Script anti-flash de tema

Para evitar o efeito indesejado de tela branca (flash) antes do carregamento do JavaScript da aplicação, um script inline síncrono é executado imediatamente no `<head>`.

**Ordem de prioridade da escolha do tema:**

* Valor salvo no `localStorage.getItem('theme')`.
* Propriedade `defaultTheme` definida no projeto (`'light'` ou `'dark'`).
* Preferência do sistema operacional (`window.matchMedia('(prefers-color-scheme: dark)')`).

O resultado final é gravado diretamente no atributo `data-theme` da tag `<html>`: `<html data-theme="dark">`.

<div style={{marginBottom: '4rem'}}></div>

### B. Skip Link de acessibilidade

O primeiro elemento do `<body>` é um link oculto focado em leitores de tela e navegação por teclado:

```html
<a href="#main-content" class="sinc-main-content-link sinc-sr-only --focusable">
  Pular para o conteúdo principal
</a>
```

Ao pressionar `Tab` logo após o carregamento da página, esse link torna-se visível, permitindo que o usuário salte direto para o `<main id="main-content">` sem precisar percorrer todo o menu de navegação.

<div style={{marginBottom: '4rem'}}></div>

### C. Overlay global (`.sinc-global-overlay`)

Um elemento `<div>` fixo no fundo da tela (`z-index: var(--z-index-overlay)`) é injetado ao final do `<body>`:

```html
<div class="sinc-global-overlay" data-global-overlay aria-hidden="true"></div>
```

**Comportamento via CSS (`:has()`):**
* Quando qualquer elemento na página ganha os atributos `[data-state="open"][data-overlay]`, o overlay global transiciona sua opacidade de `0` para `1`.
* Se o elemento tiver `data-overlay="behind"`, o `z-index` do overlay se ajusta automaticamente para ficar atrás do elemento em destaque.

**Listeners globais automáticos:**
* **Clique no overlay:** Ao clicar na área escura do overlay, o script invoca `closeOpenElements()`, fechando modais/gavetas ativas.
* **Tecla `Escape`:** Pressionar a tecla `Esc` no teclado fecha automaticamente qualquer elemento aberto na tela.

<div style={{marginBottom: '4rem'}}></div>

### D. Alternador de tema automático (`[data-theme-toggle]`)

Qualquer botão na aplicação que possua o atributo `data-theme-toggle` é automaticamente mapeado pelo script global da casca:

```html
<button data-theme-toggle aria-label="Alternar tema">
  Alternar Tema
</button>
```

Ao ser clicado, o script alterna o atributo `data-theme` na tag `<html>` entre `'light'` e `'dark'`, persiste a escolha do usuário no `localStorage` e atualiza os atributos de acessibilidade `aria-pressed` e `data-active` no botão.

<div style={{marginBottom: '4rem'}}></div>

### E. Ferramentas opcionais de acessibilidade e analytics

* **HandTalk (Libras):** Quando `handTalkToken` é fornecido, insere o widget da tradutora virtual MAYA no canto inferior da tela.
* **Google Analytics:** Quando `googleAnalyticsId` é fornecido, insere a tag síncrona `gtag.js` e inicializa o rastreamento do GA4.
